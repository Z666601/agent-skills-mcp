# xlsx-cell-diff：逐格取证 + 交付机检

两个脚本，各管一件事。都是退出码当门禁，输出直接能贴进汇报
（下面命令里的 `scripts/…` 相对本技能目录；在别处跑就写全路径
`%USERPROFILE%\.agents\skills\xlsx-cell-diff\scripts\`）：

- `scripts/cell_diff.py`——两张表比，输出逐格「改前 → 改后」+ 结构差异。用于**复审监工回路**：
  工单里写死了改了哪些格，对方报"只改了这些"，跑一遍就是证据。
- `scripts/table_check.py`——一张表自检，逐项 PASS/FAIL/SKIP 加汇总行。用于**文档交付先机检**：
  交付前必须跑完，不跑不能交。（骨架来自 2026-09 十五五交付包里的 `自检.py`，
  任务专属的页签名/列名/取值全部挪进规则 JSON。）

## 什么时候用

- 任何 xlsx 交付物交出去之前（先机检，再交）。
- 复核别人改过的表：他声称只动了 N 格，或只动了某几列。
- 台账类表格：枚举列跑没跑偏、主键有没有重复、行数与"共 X 条"的声明对不对得上、合计与总额对不对得上。
- 多轮修订之间要留证据链（round2 → round3 改了什么）。

## 流程

1. **动手前先留快照**——没有改前基线，diff 就没有意义：

   ```powershell
   Copy-Item "总表.xlsx" "总表-round3改前.xlsx"   # Git Bash: cp 总表.xlsx 总表-round3改前.xlsx
   ```

2. **改完跑逐格差异**（长报告落盘，别只在屏幕上看）：

   ```bash
   py scripts/cell_diff.py "总表-round3改前.xlsx" "总表.xlsx" --out "s14_cells.md"
   py scripts/cell_diff.py "总表-round3改前.xlsx" "总表.xlsx" --sheet 总表 --max 0 --full
   py scripts/cell_diff.py "旧.xlsx" "新.xlsx" --links     # 台账里有超链接/合并区时用
   ```

3. **跑机检门禁**（规则 JSON 放交付目录里，跟表一起留档）：

   ```bash
   py scripts/table_check.py "总表.xlsx" --rules rules.json --write
   py scripts/table_check.py "总表.xlsx" --enum "总表:当前状态=在库,已出库,待审核,未挂网" --key "总表:项目编码"
   ```

4. 汇报里贴：逐格清单（或它的路径）+ `TOTAL n 项 ｜ PASS x / FAIL y / SKIP z` 那一行。

## 退出码

| 脚本 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| cell_diff.py | 两表完全一致 | 有差异（含增删行列/页签、列序变化） | 文件或 `--sheet` 名字不对 |
| table_check.py | 全部检查跑完且全 PASS | 有 FAIL **或有 SKIP** | 参数/读文件/规则 JSON 错误 |

`table_check.py` 有 SKIP 也算没过——没跑成的检查不能当成通过。

## 规则 JSON

免规则也能跑（表头齐、无整行重复、无夹空行、无首尾空格每个页签都查）。
任务专属的东西写进 JSON，典型的中国式台账：

```json
{
  "sheets": {
    "项目台账": {
      "header_row": 1,
      "key": "项目编码",
      "required": ["项目名称", "当前状态", "责任部门"],
      "enums": {"当前状态": ["在库", "已出库", "待审核", "未挂网"]},
      "stated_rows": {"sheet": "汇总口径", "label": "项目总数"},
      "stated_sum": {
        "column": "投资额（万元）",
        "stated": {"sheet": "汇总口径", "label": "投资总额"},
        "tolerance": 0.01
      },
      "refs": {"责任部门": {"sheet": "部门清单", "key": "部门名称"}}
    },
    "部门清单": {"key": "部门名称", "required": ["负责人"]}
  }
}
```

- `key` = 一行一事项：该列必须唯一且非空。
- `stated_rows` / `stated_sum` = 对账：实际行数、列合计，要等于别的页签里写着的数。
  取数位置两种写法：`{"sheet":.., "label":"项目总数"}`（找到标签，取右邻格，取不到取下方格）
  或 `{"sheet":.., "cell":"B7"}`（直接给格号）。
- `refs` = 跨页签引用：本列每个值都得在目标页签的键列里出现。
- `enums` 里想允许空值就把 `""` 写进允许值列表，否则空格也算越界。
- `header_row` 默认 1，说明行占头就在表里写 `"header_row": 3`；`data_start` 可指定数据起始行。

## 踩过的坑（源脚本里真实存在的）

- **列按表头名找，不按列号**。客户中途挪列序很常见；两个脚本都按表头名定位，
  比对前先做全/半角括号与空白归一化，精确匹配不到才退化成唯一前缀。列名重名时
  定位会失败，这时才按列号兜底，报告会写清用了哪种对齐。
- **合并单元格的值只在左上角**。表头横跨 A1:B1 时，read_only 读 B1 是空的；
  `table_check.py` 会把左上角值扩散到整块再判空/判枚举（代价是它用普通加载而不是 read_only）。
  `cell_diff.py` 默认流式读，合并区变化要 `--links` 才报。
- **`data_only` 只有缓存值**。openpyxl 拿到的公式结果 = 上次 Excel/WPS 打开并保存时缓存的数；
  脚本刚生成的表没被 Excel 打开过，公式格一律读成 None，必填列和合计会假 FAIL。
  用 `--raw` 看公式原文，或让表在 Excel/WPS 里保存一次再机检。
- **日期和数字会回来成 float/datetime**。`44925.0` 与 `44925` 已归一化当成同值；
  文本 `"300"` 与数值 `300` 是真差异，别当噪声删掉。
- **read_only 的行宽按该行自己的 XML 记**，表头行可能比数据行短；`cell_diff.py` 对没表头的列
  按列号补比，不会静默跳过（早期版本会漏，自我比较都能报出假差异）。
- **首尾空格看得见**。`CIM一期␣` 里的 ␣ 是脚本加的；不加就会和没改过长得一样。
- **插行会刷屏**。逐格比较按行号对齐，对方插入/删除一行会让后面所有行全报成变化；
  满屏都是改动就说明他动了行序，改用主键列复核，别逐格读。
- **`--max` 会截断**（默认 300 格）。截断处在报告里留一行"还有 N 格未列出 + 复现命令"；
  要完整清单加 `--max 0`。

## 未执行纪律

- 某项检查没跑成（列找不到、页签不存在、规则 JSON 缺字段）→ 输出 `SKIP …… 未执行：<原因>。复现：<命令>`，
  汇总行计入 SKIP，进程非零退出。**绝不写 PASS，也不写"应该没问题"。**
- 汇报里对应的话只能这么写：`未执行：页签「汇总口径」不存在（现有页签 …），复现：py table_check.py "总表.xlsx" --rules rules.json`。
- 整步没跑也要认：交稿说明里写"逐格差异未执行，命令：py cell_diff.py 改前.xlsx 现表.xlsx --out s14_cells.md"，
  而不是让人以为已经比过了。
