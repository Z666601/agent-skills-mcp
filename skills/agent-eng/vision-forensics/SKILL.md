# vision-forensics — 视觉取证

你"看到"的内容是模型的重建，不是照片。真实踩坑记录：视觉模型会在缩略对比图上虚构
"位置偏移"、把抗锯齿边缘判成"粘连"、把不存在的文字"读"出来。**任何视觉读数在像素
定量复核之前都只是假设。**

## 四类任务，各走各的流程

### 1. 看图问答（这是什么 / 写了什么）

1. 整图先看一遍定布局；对文字和小控件，**先裁剪关键区再读**——缩略图上的小字读数不可信。
2. 本地图片走 `Read` → 返回 CDN URL → **直接调用**环境里的图像分析 MCP（本机为
   `mcp__4_5v_mcp__analyze_image`，同步内联返回；包装成 skill 式调用会变异步且收不到结果）。
3. CDN URL 按路径去重、约 10 分钟过期：报 400 / 错误码 1210 = 过期，重新 `Read` 刷新，
   不要反复重试旧 URL。

### 2. 图像取证对比（改得对不对 / 两张图差在哪）

1. 视觉模型报出的任何缺陷（偏移/粘连/错字/色差）→ **必须复核**：全分辨率裁剪 +
   numpy 像素定量取证，例如：
   - 逐行采样颜色（p60/p85 分位）对比渐变 ramp；
   - 区域像素差均值，阈值化后判断差异是否超出噪声。
2. 复核不成立的"缺陷"直接驳回，不改图。宁可保留原样并向用户披露，也不要按幻觉坐标擦写。
3. 结论必须带证据：采样坐标、数值、阈值——而不是"看起来不对"。

### 3. 设计稿 / 截图 → 前端代码（UI 还原）

1. 先切栅格：导航 / 主内容 / 页脚（或设计稿标出的区块），逐区处理，不要整页一把梭。
2. 逐区提取：主色/文字色（取 p60 分位而非边角像素）、字号层级、间距节奏、圆角阴影。
3. 生成后**对照原图逐区像素 diff 验收**：差异超阈值的区块回炉重做，不要"看起来挺像"就交付。

### 4. GUI 自动化（找控件 → 操作）

1. 全屏截图定位目标 → 裁剪放大确认"就是这个" → 坐标换算回原始分辨率 → 操作 → 再截图闭环验证。
2. 缩略图上量到的坐标必须乘以（原始尺寸 / 展示尺寸）换算；换算后先用一次轻量操作验证落点，
   再做连续操作。

## grounding 输出规范

- 每个定位结论 = 目标 + **像素坐标（原始分辨率）** + 证据（裁剪图或采样值）。
- 多元素定位输出清单，每项带独立证据；禁止"大概在左边"这类无坐标描述。
- 定位与行动分离：先出定位清单，确认后再批量行动。

## 已知糟粕（不要引入）

- 不引入外部视觉 API 依赖，不绑定画布类应用，不带 proxy。
- 不盲信任何 OCR / 视觉模型的一次性读数——包括本技能流程中的中间结论，一样要复核。
- 改图不做"整屏大膨胀擦除"：用各向异性小膨胀（左右窄、上下宽）保护相邻装饰元素；
  红底横幅白字类只走掩码擦除。
