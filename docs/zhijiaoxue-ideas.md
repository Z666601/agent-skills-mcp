Node.js ≥22 标准库零第三方依赖（`node:http` + `node:sqlite` + `node:test`，30 个 HTTP 接口、78 条测试），大模型用阿里云百炼 qwen-plus（OpenAI 兼容，**可选依赖**：不配密钥全流程降级可用），检索为自实现 BM25 中文分词。

## 三、可复用的 5 个工程模式（本项目最值钱的部分）

### 模式 1：双闸校验（结构闸 + 语义闸）

AI 生成的结构化输出先过纯代码规则校验（字段非空、格式合法、数量一致），再过"模型独立重解 + 比对"的语义校验，两道闸各自输出逐条问题清单。关键洞察：**不能让模型自证正确**——让它回抄整批数据会撞输出上限导致校验静默失效，必须让它独立重做一遍再比对，且只输出差异清单。适用于一切"agent 生成 → 人工审核"工作流（合同、报表、代码）。

### 模式 2：教师签发（人在回路的强制门控）

AI 生成的题目必须经教师逐题勾选确认，后端才允许发布；未勾选时 API 直接拒绝（403），前端无法绕过。签发记录带操作人身份与题目来源标记，"谁发的、题从哪来、谁判的"三可追溯。要点：**门控在后端强制而非前端按钮**。适用于一切"AI 建议 → 人做决定"的场景（医疗、法律、财务）。

### 模式 3：NULL 状态建模（AI 预处理 → 人工终审）

用数据库字段的 NULL 显式区分"机器已判定"与"等人签字"：解答题 AI 预评分后 `score` 仍为 NULL，教师给分才写入；统计函数按 NULL 与否自动切换口径，报告文案随数据状态实时变化。别把 AI 结果直接当最终结果或当 0——任何"AI 做了但人还没确认"的中间态（合同初审、数据标注、翻译）都值得一个一等公民的"未决"状态。

### 模式 4：S0/S1 双层能力（确定性兜底 + AI 增强）

每个 AI 调用点都配一条不依赖模型的降级路径：大纲→检索条目直出、出题→本地题库取样、报告→统计直出文本，降级时明确标注不冒充 AI。核心：**AI 是增益而非前提**——每个环节都回答"没有 AI 时这条路怎么走"，然后把答案写成代码。降级路径同时是最好的测试用例：去掉 AI 后流程若断了，说明流程设计有问题。

### 模式 5：人格常量注入（共享身份 + 局部改写）

多处模型调用共享同一个"人格常量"（口吻、依据资料不编造、指出错在哪一步），各任务再追加专属要求。局部改写要精确到**删除不适用的例子**（数学的典型误区描述在语文场景下摘除），否则模型会照着错误学科的示例编造。解决多环节 agent 系统"六个调用点说六种话"的一致性问题。
